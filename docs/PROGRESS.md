- M4 progress (2026-11-23): finding confirmations and deterministic scoring engine are implemented (`vio_backend/scoring.py`, `finding_store.py`, `routers/findings.py`). Added `GET /api/v1/student/findings/confirmable`, `GET /api/v1/student/findings/{finding_id}`, and `POST /api/v1/student/findings/{finding_id}/confirmations`. Endpoints enforce registered course requirement, single confirmation, and reporter/confirmer independence (also backed by PostgreSQL triggers). Scoring engine calculates verified student trust (0.65 for email-verified students), supporter contributions capped at 0.20, anomaly multiplier discounts, false-reliability factors, recency pursuit decay (1.00 down to 0.10), advance notice discounts (0.50), and clearance tiers (Tier 1: 5 distinct reports and score >= 0.80; Tier 2: 8 supporters and score >= 1.30). Score breakdowns are stored in `finding_scores` upon report creation and confirmation. 65 tests passing.
- M5 progress (2026-11-23): multi-model panel gate and adjudication engine are implemented (`vio_backend/gate.py`, `model_panel.py`, `audit.py`, `eval_service.py`). 3-model panel (safety, consistency, red-team) evaluates findings with minimum 0.80 calibrated confidence threshold. Gate implements deterministic state transitions: unanimous pass -> `cleared` with automated neutral public summary generation, any block -> `rejected`, uncertain/abstain -> `held` with 14-day hold TTL. Appends all state transitions to cryptographic hash-chained `decision_log` (`entry_hash = SHA256(prev_hash || canonical_row)`). Golden-set evaluation service (`eval_service.py`) tests canary cases and automatically trips `model_panel` circuit breaker upon quality degradation. Seed updated with M5 model registry entries. 76 tests passing.

Implemented class notice announcements, lecturer reply submission with automated assessment classification (`record_explanation`, `verify_evidence`, `refer_to_appeals`), secure one-time token link generation/redemption for authorities, authority receipt acknowledgement, official response recording, and background escalation worker (`process_overdue_escalations`) that advances unacknowledged deliveries past wait window from HOD to Dean and logs decisions to `decision_log`. Automated appeals endpoint implemented. Default FUNAAB routing steps seeded. 85 tests passing.
